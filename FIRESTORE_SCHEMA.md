# Firestore NoSQL Schema & Security Guide

## 1. Environment Variables Required

You **never** need to commit API keys to GitHub or expose private server secrets. The frontend reads these strictly through `import.meta.env` at build/runtime.

### Variables Checklist for Vercel
Add the following keys in **Vercel Dashboard → Project Settings → Environment Variables**:

| Variable Name | Description | Where to find in Firebase Console |
|---|---|---|
| `VITE_FIREBASE_API_KEY` | Public Web API Key | Project Settings → General → Your apps → Web app (`apiKey`) |
| `VITE_FIREBASE_AUTH_DOMAIN` | Auth Domain | `paisalainden.firebaseapp.com` |
| `VITE_FIREBASE_PROJECT_ID` | Project ID | `paisalainden` |
| `VITE_FIREBASE_STORAGE_BUCKET` | Cloud Storage Bucket | `paisalainden.firebasestorage.app` |
| `VITE_FIREBASE_MESSAGING_SENDER_ID` | Cloud Messaging Sender ID | Project Settings → Cloud Messaging (`Sender ID`) |
| `VITE_FIREBASE_APP_ID` | Web App ID | Project Settings → General → Your apps → Web app (`appId`) |

> [!TIP]
> **Optional WhatsApp Integration**: If using WhatsApp invoice notifications:
> - `VITE_WHATSAPP_TOKEN`: Meta for Developers system token.
> - `VITE_WHATSAPP_PHONE_ID`: Meta WhatsApp Phone Number ID.

## 2. Frontend Security Model Explained

A common concern in web development is: *"Can users steal my database using the `apiKey` in my web app?"*

1. **Firebase `apiKey` is an Identifier, Not a Master Secret**:
   Unlike a SQL password or Supabase `service_role` key, the Firebase Web API key only identifies which Google Cloud project incoming requests belong to.
2. **Access Control is Enforced by Security Rules**:
   Even if an attacker reads your `apiKey` in the browser bundle, they can only perform actions explicitly permitted by your `firestore.rules`.
3. **Database-Level Schema Validation**:
   Your repository now includes `firestore.rules` which rejects any malformed document, negative amounts, or missing required fields at the database level before any write occurs.

## 3. NoSQL Schema Design

### Collection: `students`
Stores individual student profiles.

| Field | Type | Required | Description |
|---|---|---|---|
| `id` | `string` | Auto | Unique Document ID generated by Firestore |
| `name` | `string` | **Yes** | Student's full name (min 1 char, trimmed) |
| `phone` | `string` | **Yes** | Contact phone number |
| `email` | `string \| null` | No | Optional email address |
| `subjects` | `number` | **Yes** | Number of subjects enrolled (>= 1, default 1) |
| `monthly_fee` | `number` | **Yes** | Monthly fee amount (>= 0) |
| `monthlyFee` | `number` | **Yes** | Mirrored property for camelCase frontend access |
| `class_year` | `string` | No | Grade/Class, e.g. `"Class 10"`, `"2026"` |
| `classYear` | `string` | No | Mirrored property for camelCase frontend access |
| `created_at` | `string (ISO)`| **Yes** | Creation timestamp |
| `updated_at` | `string (ISO)`| No | Last modification timestamp |

---

### Collection: `payments`
Stores payment transaction ledger records.

| Field | Type | Required | Description |
|---|---|---|---|
| `id` | `string` | Auto | Unique Document ID generated by Firestore |
| `student_id` | `string` | **Yes** | Foreign key pointing to `students/{id}` |
| `studentId` | `string` | **Yes** | Mirrored property for camelCase frontend access |
| `amount` | `number` | **Yes** | Payment amount (> 0) |
| `payment_date` | `string` | **Yes** | Payment date formatted as `YYYY-MM-DD` |
| `date` | `string` | **Yes** | Mirrored property for camelCase frontend access |
| `month_key` | `string` | **Yes** | Month applied to, formatted as `YYYY-MM` (e.g. `"2026-09"`) |
| `monthKey` | `string` | **Yes** | Mirrored property for camelCase frontend access |
| `payment_method` | `string` | **Yes** | `"online"` \| `"cash"` \| `"upi"` \| `"offline"` |
| `paymentMethod` | `string` | **Yes** | Mirrored property for camelCase frontend access |
| `created_at` | `string (ISO)`| **Yes** | Transaction record creation timestamp |

---

### Collection: `expenses`
Stores operational expenses for tuition running costs.

| Field | Type | Required | Description |
|---|---|---|---|
| `id` | `string` | Auto | Unique Document ID generated by Firestore |
| `description` | `string` | **Yes** | Expense description (min 1 char, trimmed) |
| `amount` | `number` | **Yes** | Expense amount (> 0) |
| `expense_date` | `string` | **Yes** | Date formatted as `YYYY-MM-DD` |
| `date` | `string` | **Yes** | Mirrored property for camelCase frontend access |
| `month_key` | `string` | **Yes** | Month applied to, formatted as `YYYY-MM` |
| `monthKey` | `string` | **Yes** | Mirrored property for camelCase frontend access |
| `category` | `string` | No | e.g. `"Rent"`, `"Electricity"`, `"Supplies"`, default `"General"` |
| `created_at` | `string (ISO)`| **Yes** | Expense record creation timestamp |

## 4. How to Create the Web App in Firebase Console (Step-by-Step)

If you haven't yet created the Web App within your Firebase Project `paisalainden`:

1. Open [Firebase Console](https://console.firebase.google.com/).
2. Select your project **paisalainden**.
3. On the Project Overview page, click the **Web** icon (`</>`) to add an app.
4. Enter an App nickname (e.g. `paisa-lainden-web`).
5. (Optional) Check or uncheck Firebase Hosting, then click **Register app**.
6. Firebase will display your `firebaseConfig` object:
   ```javascript
   const firebaseConfig = {
     apiKey: "AIzaSy...",
     authDomain: "paisalainden.firebaseapp.com",
     projectId: "paisalainden",
     storageBucket: "paisalainden.firebasestorage.app",
     messagingSenderId: "502134208316",
     appId: "1:502134208316:web:..."
   };
   ```
7. Copy each value into your Vercel Environment Variables.
8. Under **Build → Firestore Database**, click **Create database** (if not already created), select a location (e.g. `asia-south1`), and select **Production mode**.
9. Under the **Rules** tab in Firestore, paste the contents of `firestore.rules` from this project and click **Publish**.
